# GATE CS 2027 portal

A static study site for GATE CS 2027 (Vite, React 19, TypeScript, Tailwind 4), published on
GitHub Pages. Content is data. Chapter files live in `data/` and the study memory
(derivations, solved PYQs, the paper ledger) lives in `memory/`. The validators in `scripts/`
are the schema, and every rule they enforce has a mutation test that proves it fails.

**New machine? Read `docs/SETUP.md` first.** **Start every session by reading `memory/STATUS.md`.** It is generated from the files, so it
says exactly what is done. Never re-extract or re-solve anything listed there.

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | dev server; re-validates and re-emits site data on every `data/` or `memory/` edit |
| `npm run build` | type-check, validate, emit `src/generated/`, bundle `dist/` (missing chapters allowed) |
| `npm run build:strict` | the same, but all 45 chapters must exist |
| `npm run test` | validator mutation tests, then unit tests (vitest) |
| `npm run check` | validate every chapter file and the whole memory layer |
| `npm run memory` | validate `memory/`, then regenerate `memory/STATUS.md` and the chapter map below |
| `npm run test:e2e` | build, then the Playwright smoke test: every route, console errors fail it |
| `node scripts/check-manifest.mjs --chapter <id>` | validate one chapter file |
| `node scripts/check-memory.mjs --chapter <id>` | validate one chapter's derivations and PYQs |
| `node scripts/check-memory.mjs --paper <id>` | validate one ledger paper |

Install with `npm install --registry https://registry.npmjs.org/`; the default registry on
this machine needs credentials.

## Directory taxonomy

```
data/
  subjects.json              skeleton: 11 subjects, 45 chapters, ids, refs, page ranges
  official-syllabus.json     the official 2027 syllabus items, each mapped to one chapter
  chapters/<id>.json         one chapter's content (contract: docs/CONTENT_AUTHORING.md)
  study-plan.json            plan, priorities, time split
  references.json            per-chapter reading links
  curriculum_manifest.json   generated by scripts/build-manifest.mjs, never edited
memory/                      the study memory, see "Memory layer"
  STATUS.md                  generated progress table
  pyq/papers/<paper>.json    ledger: all 65 questions of one official paper
  chapters/<id>/derivations.md
  chapters/<id>/gate_pyqs.json
scripts/                     validators, their mutation tests, data emitters
  lib/                       rules shared by validators and emitters
src/
  content/                   types and loaders for src/generated/
  features/<feature>/        one folder per feature: quiz, progress, pyq, papers, decade (10-year
                             marks view), review (spaced repetition), mock (65-question paper),
                             insights (weak topics, trends, error log), offline, visuals, ...
  ui/                        design-system primitives; ui/3d/ holds the three.js scenes
  generated/                 emitted site data: gitignored, rebuilt by the Vite plugin
public/diagrams/             diagram-design SVGs; pyq/ holds each solved PYQ's drawings (<id>.svg)
design/stitch/               Stitch screens, a visual reference only (their text is invented)
docs/                        SETUP.md, CONTENT_AUTHORING.md, GATE_PORTAL_FEATURES.md, agents/ (contracts)
source/                      gitignored, per machine: notes PDF, extracts, papers/ (see docs/SETUP.md)
```

Data flows one way: `data/` + `memory/` → validators → `scripts/emit-site-data.mjs` →
`src/generated/` → the app. Nothing in `src/` reads `data/` or `memory/` directly.

## Memory layer

`memory/` holds the work that is expensive to redo: the paper ledger (`memory/pyq/papers/`),
solved PYQs and derivations (`memory/chapters/<id>/`). A file there is final once `npm run memory` passes;
later sessions extend it and never regenerate it. The full schema, id and key syntax, and the
sourcing rules live in `.claude/rules/memory-layer.md`, which loads whenever a file under
`memory/` or `docs/agents/` is touched. Agents get that path in their contract.

## Claude memory files

| File | Loads | Holds |
|---|---|---|
| `CLAUDE.md` | every session | this file: stack, commands, layout, standards |
| `CLAUDE.local.md` | every session, gitignored | machine-specific paths and quirks |
| `.claude/rules/memory-layer.md` | on `memory/`, `docs/agents/` | ledger, PYQ and derivation schema, sourcing |
| `.claude/rules/chapter-content.md` | on `data/` | chapter authoring pointers |
| `.claude/rules/validators.md` | on `scripts/` | mutation-test rule, generated files |
| `.claude/rules/visuals.md` | on `src/features/visuals/`, `src/ui/3d/` | registry, 3D, e2e for sims |
| `.claude/rules/e2e.md` | on `e2e/` | Playwright runs against `dist/` |

A rule file is path-scoped by its `paths` globs. `node scripts/check-claude-memory.mjs` (part
of `npm run check` and `npm run test`) fails when this file passes 200 lines, a rule has no
`paths` or a glob matches nothing, or a path named here or in a rule no longer exists.

## Coding standards

- TypeScript is strict, with no `any` and no non-null assertions. `src/content/types.ts`
  mirrors the validators; change both together.
- All math is KaTeX. Prose fields carry inline `$…$`, rendered by `MathText`. Standalone
  formulas are TeX strings rendered by `Tex`. Derivation markdown is pre-rendered at build time.
- Zero filler. No meta-commentary about the notes, no AI-writing stock phrases, no emoji. The
  banned list lives in `scripts/lib/rules.mjs`, and the validators reject every entry.
- Comments say why, never what. Functions do one thing, names reveal intent, and each feature
  keeps its components, state and tests in its own folder.
- A rule that matters is enforced in code. Add a validator rule and its mutation test, and
  watch the test fail before the rule passes.
- Scoring follows GATE marking: MCQ +m or −m/3, MSQ all or nothing, NAT inside the range,
  and no negative marks for MSQ or NAT. `src/features/quiz/scoring.ts` is the only scorer.
- The site is static and works from any Pages path: `base: './'`, hash routing, and fonts and
  libraries bundled rather than loaded from a CDN.

## Working rules

- Chapter content follows `docs/CONTENT_AUTHORING.md`. `os-cpu-scheduling.json` is the
  exemplar.
- Run at most 4 agents at once. Agents inherit nothing, so give each one the contract by file
  path. Review agents are read-only.
- The user builds, pushes and deploys. Commit only when asked.
