# Agent contract: learning aids for solved PYQs

You add four optional fields to questions already solved in `memory/chapters/<chapter>/gate_pyqs.json`:
`hints`, `solution.recognize`, `solution.check` and `variation`. A learner meets a question cold,
tries it alone, then asks for help one rung at a time. The aids are that ladder. Read
`.claude/rules/memory-layer.md` and the validator (`checkHints`, `checkVariation`,
`checkRecognize`, `checkCheck` in `scripts/check-memory.mjs`) first. The exemplar is
`gate-cse-2026-s2-q23` in `memory/chapters/os-cpu-scheduling/gate_pyqs.json`.

**No network.** Use only local files. Never fetch from the web or download anything; a security
monitor flags it.

## Your batch

The lead names a chapter and a batch size. Take the next questions, in file order, that have no
`hints` yet. Touch nothing else in the file: never change `stem`, `options`, `answer`, `key`,
`keyNote`, `solution.steps`, `solution.shortcut`, `solution.traps`, `sources` or any diagram.
Other agents edit other chapters at the same time. No npm scripts, no git.

## The four fields

**hints** (3 to 5, kinds strictly in this order, skipping a rung is fine):
`guide` (a question that points at what is being asked), `concept` (recall the idea),
`principle` (the rule that decides it), `setup` (how to set the problem up, no numbers solved),
`partial` (one concrete step done). Each hint is one small nudge in your own words. It must never
state the answer, say "the answer is", repeat another hint, or copy a solution step. Check that a
learner reading only the hints cannot read off the option. On a marks-to-all or disputed-key
question never assert which option is correct.

**solution.recognize** `{concept, clues, contrast?}`: `concept` is a topic id of this chapter
(`data/chapters/<chapter>.json`), the one that teaches the method. `clues` names the words or
features in the question that point to it. `contrast` names the look-alike concept and how to tell
them apart. Specific to this question, never generic.

**solution.check** `{body, tex?}`: an independent check on the result, by substitution, a boundary
case or a second route. It must not just restate the last step.

**variation** `{stem, options?, answer, explanation}`: the same method on new numbers or a new
instance, the same `type` as the question (MCQ four distinct options and an index 0 to 3; MSQ
four options and an array of indices; NAT no options and a number). It is labelled "generated by us"
in the app, so it is not an exam question and must not copy the stem. **Compute the variation's
answer by a script** (enumeration, simulation or direct calculation, in a scratch directory outside
the repo that you create yourself), and make each wrong option a real mistake, not filler. The
explanation shows the method in two to four sentences. A question whose point is a figure may have
a text-only variation or none.

If you cannot write one of the fields well, leave it out and report it. A missing aid is honest;
a filler aid teaches something false. Never invent facts about the exam.

## Style

Plain words first, jargon second. Math is `$...$` inline. No emoji, no meta-commentary ("the
notes say"), no stock AI phrases; the validator rejects the banned list in `scripts/lib/rules.mjs`.
Edit the JSON with a small script that loads, changes only your questions and writes back with
`ensure_ascii=False` and the file's existing 2-space indent.

## Done

`node scripts/check-memory.mjs --chapter <chapter>` prints a check mark. Report how many
questions you finished and how many remain without `hints`.
