# Network layer: derivations

## Masks, network and broadcast addresses, and host counts
<!-- topics: cn-network-layer.cidr, cn-network-layer.ipv4-addressing -->

**Claim.** Treat an IPv4 address as a 32-bit unsigned integer $x$ and let $0 \le n \le 32$ be the prefix length. The mask of a /n block is

$$M_n = 2^{32} - 2^{32-n},$$

the integer with $n$ leading 1s and $32 - n$ trailing 0s. The block containing $x$ is the set of $2^{32-n}$ addresses that share $x$'s top $n$ bits, with

$$\text{network} = x \wedge M_n = 2^{32-n} \left\lfloor \frac{x}{2^{32-n}} \right\rfloor, \qquad \text{broadcast} = x \vee \lnot M_n = \text{network} + 2^{32-n} - 1.$$

For $n \le 30$ the block has $2^{32-n} - 2$ assignable host addresses. In the first mask octet $m$ that is not 255, the block size is $256 - m$, and the network's octet is the address's octet rounded down to a multiple of $256 - m$; the later octets are 0 in the network and 255 in the broadcast. In classful addressing, class A (leading bit 0) has $2^7$ network numbers of $2^{24} - 2$ hosts each, class B (leading bits 10) $2^{14}$ networks of $2^{16} - 2$ hosts, and class C (leading bits 110) $2^{21}$ networks of $2^8 - 2$ hosts.

**Derivation.** The mask is $\sum_{i=32-n}^{31} 2^i$, a geometric series equal to $2^{32} - 2^{32-n}$. ANDing with it keeps bits $31, \dots, 32-n$ of $x$ and clears the low $32 - n$ bits, which is $x$ minus its remainder modulo $2^{32-n}$, so the network address is $x$ rounded down to a multiple of $2^{32-n}$. ORing with $\lnot M_n$ sets the low $32-n$ bits, which adds $2^{32-n} - 1$ to the network address. Every address between the two shares the top $n$ bits, and there are $2^{32-n}$ of them because the free bits take every pattern once. The all-0s host part names the network itself and the all-1s host part is the directed broadcast, so neither can be given to a host, which leaves $2^{32-n} - 2$. For $n = 31$ the formula gives 0 and for $n = 32$ it gives $-1$; real /31 point-to-point links (RFC 3021) and /32 host routes are exceptions that GATE does not use unless it says so.

For the shortcut, write $n = 8q + r$ with $0 \le r < 8$. Octets $1, \dots, q$ of the mask are 255 and octet $q+1$ is $m = 256 - 2^{8-r}$ (when $r = 0$ this is $m = 0$). So $256 - m = 2^{8-r}$, and clearing the low $8 - r$ bits of octet $q+1$ is rounding it down to a multiple of $2^{8-r}$. The octets after it are entirely host bits, so they become 0 in the network address and 255 in the broadcast.

For the classes, a class whose leading $t$ bits are fixed owns $2^{32-t}$ addresses, which is half, a quarter and an eighth of the space for A, B and C. Class A uses the first octet for the network: one fixed bit leaves 7 network bits and 24 host bits. Class B fixes 2 bits of a 16-bit network part (14 free) and class C fixes 3 bits of a 24-bit network part (21 free). Class A loses networks 0 and 127 to "this network" and loopback, so 126 are usable.

**GATE use.** The 1-mark question gives IP/n and asks for the network, broadcast, first or last host, or the host count. The trap is a prefix that ends inside the third octet, where the last octet of the broadcast is 255 and the third octet changes too. A second trap is quoting $2^{24}$ hosts for class A: that is the address count, and the usable count is $2^{24} - 2 = 16\,777\,214$.

**Check.** 10.1.77.130/19: $M_{19} = 2^{32} - 2^{13} = 4\,294\,959\,104$, which is 255.255.224.0. The third mask octet is 224, block size 32, and 77 rounds down to 64, so the network is 10.1.64.0, the broadcast 10.1.95.255 and the hosts number $2^{13} - 2 = 8190$. 192.168.13.200/27: mask octet 224 in the fourth octet, 200 rounds down to 192, giving 192.168.13.192 to 192.168.13.223 with 30 hosts. A script compared the block-size shortcut with the bitwise AND on 20 000 random addresses and prefixes from /1 to /30.

## Subnet counts and host bits
<!-- topics: cn-network-layer.subnetting -->

**Claim.** Borrowing $s$ host bits of a /n block as a subnet field gives $2^s$ subnets of prefix $/(n+s)$, each holding $2^{32-n-s}$ addresses and $2^{32-n-s} - 2$ hosts, for $n + s \le 30$. For $k$ subnets the fewest borrowed bits is $s = \lceil \log_2 k \rceil$. For $h$ hosts per subnet the fewest host bits is $b = \min\{b : 2^b - 2 \ge h\}$, so the prefix is $/(32 - b)$. A design that needs both is possible exactly when $s + b \le 32 - n$. Under the older classful convention that discarded the all-0s and all-1s subnet numbers, the subnet count is $2^s - 2$.

**Derivation.** An address in the block is its fixed $n$-bit prefix followed by $32 - n$ free bits. Split the free bits into the first $s$ (the subnet number) and the remaining $32 - n - s$ (the host number). This split is a bijection between the block's addresses and pairs (subnet number, host number), so there are $2^s$ subnets, each the set of addresses with one fixed subnet number, which is a /(n+s) block. Applying the host count of the previous section to a /(n+s) block gives $2^{32-n-s} - 2$. The subnet field must number $k$ subnets, so $2^s \ge k$, and the smallest such $s$ is $\lceil \log_2 k \rceil$. A subnet with $b$ host bits holds $2^b - 2$ hosts, which increases with $b$, so the least $b$ with $2^b - 2 \ge h$ is the longest prefix that still fits $h$ hosts. The prefix $n$, the subnet field and the host field share 32 bits, which gives $s + b \le 32 - n$.

**GATE use.** Questions ask how many subnets and hosts a mask yields, which mask gives at least $k$ subnets, or which prefix fits $h$ hosts. The trap is $h = 2^b - 1$ or $h = 2^b$: 31 hosts do not fit in 5 host bits, because $2^5 - 2 = 30$. Apply $2^s - 2$ for the subnet count only when a question invokes the old rule.

**Check.** A /24 split into /26 gives $2^2 = 4$ subnets of $2^6 - 2 = 62$ hosts, and into /28 gives 16 subnets of 14 hosts. Ten subnets need $s = 4$, since $2^3 = 8 < 10 \le 16$. The host-bit rule gives $b = 7$ (/25) for 100 hosts, $b = 6$ (/26) for 50, $b = 5$ (/27) for 20 and 30, and $b = 6$ for 31.

## VLSM: allocating the largest block first never fails
<!-- topics: cn-network-layer.subnetting -->

**Claim.** Let a parent block hold $P = 2^p$ addresses and start at an address aligned to $P$. Request blocks of sizes $z_1 \ge z_2 \ge \dots \ge z_k$, each a power of two (the size of the prefix chosen for each subnet's host count). Placing them in this order, each at the lowest free address, puts block $i$ at offset $S_i = z_1 + \dots + z_{i-1}$ from the start of the parent. Every block is then aligned, no two overlap and no gap is left, so the allocation succeeds exactly when $\sum_i z_i \le P$. Any valid allocation, in any order, needs $\sum_i z_i \le P$ too, so largest-first succeeds whenever any allocation exists. A block of size $z$ is a valid CIDR block only when its start is a multiple of $z$.

**Proof.** A /m block is the set of addresses with fixed top $m$ bits, so it starts at a multiple of its size $2^{32-m}$; an interval of the right length that starts elsewhere has no prefix (the trap in allocation options). For the placement, every $z_j$ with $j < i$ is a power of two at least $z_i$, hence a multiple of $z_i$, so their sum $S_i$ is a multiple of $z_i$. The parent starts at a multiple of $P$, which is a multiple of $z_i$, so block $i$ starts at an address aligned to its own size. The blocks occupy the consecutive intervals $[S_i, S_i + z_i)$, which neither overlap nor leave gaps, and the last ends at $\sum_i z_i$, so they fit in the parent exactly when $\sum_i z_i \le P$. Conversely, disjoint blocks inside the parent occupy $\sum_i z_i$ distinct addresses out of $P$.

Order matters for the naive method, which puts each block at the next aligned address after the previous one and never goes back to fill a gap. With sizes 64, 128, 64 in a /24, the first block takes offset 0, the 128 block cannot start at 64 and moves to 128, and the second 64 block finds no room after 256, although the sizes add up to exactly 256. Lowest-free placement would go back to offset 64; sorting removes the need to. Sorted as 128, 64, 64 they fill offsets 0, 128 and 192.

**GATE use.** Two shapes recur. "Allocate subnets for these host counts from this block" is solved by sizing each subnet with the host-bit rule and placing the largest first. "Which allocation is valid?" is solved by checking for every block that its start is a multiple of its size, that it lies inside the parent and that it overlaps no other. The trap is a block such as a /21 whose third octet starts at 36: a /21 has size 8 in the third octet, and $36 \bmod 8 = 4$.

**Check.** 200.10.20.0/24 for 100, 50 and 20 hosts needs sizes 128, 64 and 32, placed at 200.10.20.0/25, 200.10.20.128/26 and 200.10.20.192/27, which leaves 200.10.20.224/27 free. A script ran largest-first placement on all 27 338 nonincreasing multisets of powers of two with sum at most 64 inside a 64-address parent, and every block was aligned and contiguous with the one before it.

## CIDR blocks nest or are disjoint, and when blocks aggregate
<!-- topics: cn-network-layer.route-aggregation-lpm -->

**Claim.** (a) Two CIDR blocks are either disjoint or one contains the other. (b) A set of $2^k$ blocks, all /n, has a union that is exactly one /(n−k) block if and only if the blocks are consecutive and the first starts at a multiple of the aggregate size $2^{32-n+k}$. (c) The smallest single prefix covering an address range from $lo$ to $hi$ is the longest common prefix of $lo$ and $hi$ in binary; when the range is not a whole aligned block, that prefix also covers addresses outside the range.

**Proof.** (a) Let blocks $B$ and $B'$ have prefix lengths $n \le n'$ and share an address $x$. Every address in $B'$ agrees with $x$ in its top $n'$ bits, hence in its top $n$ bits, and $B$ is exactly the set of addresses agreeing with $x$ in the top $n$ bits, so $B' \subseteq B$. (b) A /(n−k) block is the set of addresses with fixed top $n-k$ bits. The next $k$ bits take $2^k$ values, and fixing them splits the block into $2^k$ consecutive /n blocks, the first of which starts at the aggregate's network address, a multiple of $2^{32-n+k}$. Conversely, if the union of the given blocks equals some /(n−k) block, its lowest address is the first block's start, which is that block's network address and so a multiple of $2^{32-n+k}$, and the given blocks are its $2^k$ /n pieces, which are consecutive. (c) A prefix covers both $lo$ and $hi$ only if $lo$ and $hi$ agree on its bits, so its length is at most the length $\ell$ of their longest common prefix, and the /ℓ prefix of $lo$ covers every address between them. The /ℓ block has exactly $hi - lo + 1$ addresses only when the range is an aligned block; otherwise the extra addresses belong to other networks.

**GATE use.** NAT-type questions ask for the prefix length of the aggregate of given blocks. Count the leading bits common to the first and last address, then confirm the alignment. The trap is aggregating unaligned blocks, which would advertise addresses that belong to someone else.

**Check.** 140.20.32.0/21 and 140.20.40.0/21 cover third octets 32 to 47, which are 00100000 and 00101111 in binary: the common prefix is 4 bits of the third octet, 16 + 4 = 20 in all, and $32 \bmod 16 = 0$, so the aggregate is 140.20.32.0/20. The /21 blocks 140.20.72.0/21 and 140.20.80.0/21 cover third octets 72 to 87 and fail: $72 \bmod 16 = 8$, and 72 and 87 (01001000 and 01010111) share only 010, so the smallest cover is 140.20.64.0/19, which also claims third octets 64 to 71 and 88 to 95. A script confirmed (a) on 20 000 random pairs of blocks.

## Longest prefix match picks the most specific route
<!-- topics: cn-network-layer.route-aggregation-lpm, cn-network-layer.network-layer-functions -->

**Claim.** Forwarding is the per-datagram lookup of a destination in a table of prefixes; routing is the process that fills the table. For a destination $x$, the table entries whose prefix matches $x$ form a chain under containment. The entry with the longest prefix among them is unique and is the smallest block containing $x$, so longest prefix match selects the most specific route regardless of the order of the rows. The default route 0.0.0.0/0 has $n = 0$, matches every address, and is chosen only when no other entry matches.

**Proof.** Each matching entry is a block containing $x$, so any two of them intersect, and by part (a) of the previous section one contains the other. A chain of blocks ordered by containment is also ordered by prefix length, since a longer prefix gives a smaller block. Two distinct entries with the same length that both match $x$ would both equal the block of $x$'s top $n$ bits, so they are the same prefix; hence the longest match is unique. The /0 block is the whole address space, the largest element of every chain, so it is the longest match only when it is the only match. An aggregate and an exception inside it can therefore share one table: addresses inside the exception match both and take the longer one, and the rest match only the aggregate.

**GATE use.** The 2-mark MCQ gives a forwarding table and several destinations and asks for each output interface. Test each entry by comparing the first $n$ bits, or by checking that the destination lies between the entry's network and broadcast addresses, and then take the largest $n$. The trap is stopping at the first matching row.

**Check.** With 172.20.0.0/16 on link 1, 172.20.64.0/18 on link 2 and 0.0.0.0/0 on link 3, the /18 covers third octets 64 to 127. 172.20.100.5 matches all three and goes to link 2; 172.20.130.1 and 172.20.63.255 match only the /16 and the default and go to link 1; 8.8.8.8 matches only the default and goes to link 3. A script reproduced the four lookups.

## IPv4 header sizes, offset units and TTL
<!-- topics: cn-network-layer.ip-header, cn-network-layer.ip-support-protocols -->

**Claim.** The IPv4 header is $4 \times \text{IHL}$ bytes with $5 \le \text{IHL} \le 15$, so it runs from 20 to 60 bytes and options take at most 40. The payload is $\text{Total Length} - 4 \times \text{IHL}$ bytes, and a datagram has at most $2^{16} - 1 = 65\,535$ bytes. The 13-bit fragment offset counts 8-byte units, which is why every fragment except the last carries a multiple of 8 data bytes. A datagram sent with TTL $t$ is dropped by the $t$-th router it reaches, so it crosses at most $t - 1$ routers and reaches a destination behind $r$ routers only if $t \ge r + 1$. Traceroute's probe with TTL $k$ draws an ICMP time-exceeded message from the $k$-th router on the path.

**Derivation.** The fixed header is five 32-bit words: version (4 bits), IHL (4), type of service (8) and Total Length (16); identification (16), flags (3) and fragment offset (13); TTL (8), protocol (8) and header checksum (16); the source address (32); and the destination address (32). That is $160$ bits, or 20 bytes, so IHL is at least 5. IHL has 4 bits, so it is at most 15, which gives $4 \times 15 = 60$ bytes. Total Length has 16 bits and counts header plus data, which gives the payload formula and the 65 535-byte cap.

For the offset, flags and offset share one 16-bit half-word, so the offset has 13 bits. The first data byte of a fragment can lie anywhere up to index $65\,535 - 20 - 1 = 65\,514$, which would need 16 bits in byte units. In 8-byte units the largest offset is $(2^{13} - 1) \cdot 8 = 65\,528 \ge 65\,514$, so 13 bits cover every datagram, but only fragment boundaries at multiples of 8 can be expressed. Every fragment after the first starts where the previous one ends, so every fragment except the last must carry a multiple of 8 bytes.

For TTL, each router decrements it by 1 and discards the datagram when the result is 0, sending ICMP time exceeded to the source. After $j$ routers the TTL is $t - j$, so router $t$ is the first to reach 0, and the destination host behind $r$ routers receives the datagram with TTL $t - r$, which must be at least 1. A routing loop therefore holds a datagram for at most $t$ hops. Traceroute sends probes with $t = 1, 2, 3, \dots$; probe $k \le r$ dies at router $k$, whose time-exceeded reply reveals its address, and probe $r + 1$ reaches the destination. Because TTL changes at every hop, the header checksum, which covers only the header, is recomputed at every router.

**GATE use.** NAT questions give IHL and Total Length and ask for the payload, or ask for the header's range in bytes; the trap is reading IHL as bytes. TTL questions ask how many routers a datagram with a given TTL can cross, or how many time-exceeded messages traceroute collects; the trap is treating TTL as seconds.

**Check.** IHL 5 and 15 give 20 and 60 bytes. Total Length 1500 with IHL 6 leaves $1500 - 24 = 1476$ payload bytes. A datagram with TTL 1 dies at the first router, and a ping across 3 routers needs TTL at least 4. A script confirmed the field widths sum to 160 bits and that $8191 \cdot 8 = 65\,528$.

## Fragment count, offsets and lengths
<!-- topics: cn-network-layer.fragmentation -->

**Claim.** A datagram carrying $D$ data bytes (its Total Length minus its header) crosses a link with MTU $\text{MTU}$, and each fragment gets a header of $H$ bytes. Every fragment except the last carries

$$d = 8 \left\lfloor \frac{\text{MTU} - H}{8} \right\rfloor$$

data bytes, there are $\lceil D/d \rceil$ fragments, fragment $j$ (counting from 0) has offset $j d / 8$, and the last carries $D - (\lceil D/d \rceil - 1) d$ bytes. MF is 1 on every fragment but the last, all fragments keep the original identification, and fragment $j$'s Total Length is its data plus $H$. When a fragment with offset $o$ and flag MF is fragmented again, its pieces get offsets $o + j d'/8$, and the last piece inherits the flag MF. Only the destination reassembles.

**Derivation.** A fragment's Total Length may not exceed the MTU, so it carries at most $\text{MTU} - H$ data bytes. Every fragment but the last must carry a multiple of 8 (previous section), and the largest multiple of 8 not above $\text{MTU} - H$ is $8 \lfloor (\text{MTU} - H)/8 \rfloor$. Filling every fragment but the last with $d$ bytes minimises the count, and $c$ fragments carry at most $cd$ bytes, so the count is the least $c$ with $cd \ge D$, which is $\lceil D/d \rceil$. Fragment $j$ starts at data byte $jd$ of the original, and the offset is that index divided by 8. MF tells the receiver that more data follows, so it is 0 only on the fragment holding the final byte. The receiver groups fragments by (source, destination, identification, protocol), places each at byte $8 \times \text{offset}$, and knows the total length once the fragment with MF = 0 arrives.

A second fragmentation splits one fragment's data, which starts at original byte $8o$, so a piece starting $j d'$ bytes later has offset $o + j d'/8$. If the fragment was not the last of the original, data still follows its last piece, so that piece keeps MF = 1. Fragments of one datagram may take different paths and be split again on the way, so only the destination sees them all, and the loss of any one fragment loses the whole datagram. The bytes on the wire grow from $D + H$ to $D + \lceil D/d \rceil H$.

**GATE use.** The 2-mark NAT asks for the number of fragments, the offset or Total Length of a given fragment, or its MF bit. The traps are dividing $\text{MTU} - H$ without rounding down to a multiple of 8, giving the offset in bytes, counting the original header as data, and setting MF = 0 on the last piece of a refragmented middle fragment.

**Check.** 4000 data bytes, $H = 20$, MTU 1500: $d = 8 \lfloor 1480/8 \rfloor = 1480$ and $\lceil 4000/1480 \rceil = 3$ fragments of 1480, 1480 and 1040 bytes, with offsets 0, 185 and 370, MF 1, 1, 0 and Total Lengths 1500, 1500 and 1060. With MTU 1000, $d = 976$, since 980 is not a multiple of 8. The second fragment (1480 bytes, offset 185, MF 1) crossing an MTU of 620 has $d' = 600$ and splits into 600, 600 and 280 bytes with offsets 185, 260 and 335, all with MF 1, and Total Lengths 620, 620 and 300. A script rebuilt the byte layout from the offsets for every $D$ from 1 to 2999 in steps of 7 under six MTUs.

## NAPT: port capacity, inbound traffic and checksums
<!-- topics: cn-network-layer.nat -->

**Claim.** A NAPT router that shares one public address keys each mapping by (public port, transport protocol), so it holds at most $2^{16} - 1$ concurrent mappings per protocol (port 0 is not used), or 64 512 if it hands out only ports 1024 to 65 535. An unsolicited packet from outside is delivered only if a mapping for its destination port already exists, which happens only after outgoing traffic or static configuration (port forwarding). Each rewrite changes the IP header checksum and the TCP or UDP checksum.

**Derivation.** A reply from outside carries only the public address and a public port to identify the inside host, so the map from active inside pairs (private address, private port) to public ports must be injective; two pairs sharing a public port would make replies to that port ambiguous. An injective map into a set of $2^{16} - 1$ usable ports has at most that many active pairs. A router that also keys on the remote endpoint can reuse a port towards different destinations, but the per-port reasoning is what GATE expects. Entries are created when an inside packet leaves, so a packet arriving for a port with no entry has no inside destination and is dropped. The IP header checksum covers the source and destination addresses, and the TCP and UDP checksums cover a pseudo-header that contains both addresses as well as the ports, so changing the address or the port invalidates both. Protocols that write addresses into their payload, such as active-mode FTP, are not repaired by header rewriting, which is the end-to-end breakage.

**GATE use.** MCQs ask what NAT rewrites (source address and port outbound, destination address and port inbound), why an outside host cannot reach an inside host, or how many concurrent connections one public address supports. The trap is thinking NAT needs no checksum work because only the IP layer changes.

**Check.** Inside hosts 192.168.1.10:5000 and 192.168.1.11:5000 both open connections through public address 203.0.113.5. The router maps them to ports 40001 and 40002, since one public port cannot serve both. A reply to 203.0.113.5:40002 is rewritten to 192.168.1.11:5000, and a packet to port 40003 with no entry is dropped. The port count is $65\,535 - 1024 + 1 = 64\,512$.

## Bellman-Ford: what a distance vector computes
<!-- topics: cn-network-layer.distance-vector, cn-network-layer.routing-overview -->

**Claim.** In a connected network with positive link costs $c(x, v)$, the least costs $d_x(y)$ satisfy, for $x \ne y$,

$$d_x(y) = \min_{v \in N(x)} \big( c(x, v) + d_v(y) \big),$$

and a neighbour achieving the minimum is a correct next hop. Start from $D^0_x(x) = 0$ and $D^0_x(y) = \infty$ for $y \ne x$, and let every router apply $D^{k}_x(y) = \min_{v \in N(x)} \big( c(x, v) + D^{k-1}_v(y) \big)$ in synchronous rounds. Then $D^k_x(y)$ is the least cost of an $x$–$y$ path with at most $k$ links. The vectors stop changing after $h \le N - 1$ rounds, where $h$ is the largest number of links any pair needs on a least-cost path, and the final values are the true least costs. A router's own previous estimate plays no part in the update.

**Proof.** For the equation, every $x$–$y$ path with $x \ne y$ starts with a link to some neighbour $v$ and continues with a $v$–$y$ path costing at least $d_v(y)$, so its cost is at least $c(x, v) + d_v(y)$, which is at least the minimum. The neighbour $v^*$ achieving the minimum, followed by a least-cost $v^*$–$y$ path, achieves it, so equality holds, and the first link of that path makes $v^*$ a next hop. This is optimal substructure: a suffix of a shortest path is a shortest path.

For the rounds, induct on $k$. For $k = 0$ the only path with no links joins $x$ to itself. For $k \ge 1$ and $x \ne y$, a path with at most $k$ links is a link $(x, v)$ followed by a $v$–$y$ path with at most $k - 1$ links, whose least cost is $D^{k-1}_v(y)$ by hypothesis; minimising over $v$ is the update. Least-cost paths are simple because costs are positive, so they have at most $N - 1$ links. Once $k$ reaches $h$, every pair's least cost is attained, and further rounds change nothing, so the iteration stabilises at round $h \le N-1$. Kurose and Ross state the asynchronous version: with stale or delayed vectors the estimates still converge to the least costs as long as each router keeps sending updates.

**GATE use.** The 2-mark MCQ gives a router's link costs to its neighbours and their advertised vectors and asks for the new vector or a next hop. Add link cost to advertisement for each neighbour and take the minimum. The trap is choosing the neighbour with the smallest advertisement or the cheapest link instead of the smallest sum. Questions about rounds to converge use the $k$-link reading.

**Check.** X has neighbours Y (cost 2) and Z (cost 5); Y advertises 6 to D and Z advertises 1. Then $D_X(D) = \min(2 + 6, 5 + 1) = 6$ via Z, although Y is the cheaper link. A script ran synchronous rounds on 300 random connected graphs of up to 8 routers; the result matched Dijkstra from every source, and the number of changing rounds equalled $h$ in every case.

## Count to infinity and split horizon
<!-- topics: cn-network-layer.count-to-infinity -->

**Claim.** On the line A–B–C with unit costs, let link B–C fail when $D_A(C) = 2$ via B and $D_B(C) = 1$. If B and A update alternately, B starting, B's distances to C run $3, 5, 7, \dots$ and A's run $4, 6, 8, \dots$, each update adding the cost of link A–B. With RIP's infinity of 16 the two reach 16 after 15 updates, and datagrams for C loop between A and B until then. Split horizon (never advertise a route to the neighbour it was learned from) and poison reverse (advertise it to that neighbour with distance $\infty$) make B see no route via A, so B marks C unreachable at once. Neither stops a loop through three or more routers.

**Derivation.** When B–C fails, B's only neighbour is A, whose last vector says 2 to C. The Bellman-Ford update gives $D_B(C) = 1 + 2 = 3$ via A, because B cannot tell that A's route runs through B. A's next hop for C is B, so A must accept B's new value: $D_A(C) = 1 + 3 = 4$. Each update now adds 1 to the other router's last value, so after B's $i$-th update $D_B(C) = 2i + 1$ and after A's $i$-th $D_A(C) = 2i + 2$. A reaches 16 at its 7th update (the 14th update in all), and B's 8th update gives $\min(16, 17) = 16$, the 15th. Each router points at the other throughout, which is the loop.

With split horizon, A's route to C was learned from B, so A omits C from what it sends B (or, with poison reverse, sends $\infty$). B's minimum over neighbours is then $\infty$, and it tells A, which also goes to $\infty$. The rule blocks the two-router exchange because B can learn a route from A only while A's route does not go through B. Three routers defeat it: let A, B and C form a triangle with unit costs and D hang off C, so A and B reach D via C at distance 2. When C–D fails, C sets $\infty$ and tells A and B. If A hears this while B's last vector still says 2, A adopts 3 via B. B hears C's $\infty$ and then A's new vector, which omits D because A now routes through B, so B goes to $\infty$. A advertises 3 to C, since A learned it from B rather than C, so C adopts 4 via A and tells B, which adopts 5 via C, and the loop A to B to C to A counts upward. Kurose and Tanenbaum give the same examples. Hold-down timers, triggered updates and the small infinity of 16 bound the damage rather than prevent it.

**GATE use.** The 1-mark MCQ asks what follows a link failure, which technique fixes it, or the distance a router holds after a given number of exchanges. The trap is assuming B marks C unreachable at once without split horizon, or that split horizon fixes every loop.

**Check.** A script ran the alternating updates and printed B 3, A 4, B 5, …, B 15, A 16, B 16: 15 updates. With split horizon B computes $\min(\infty, 1 + \infty) = \infty$. The three-router trace gave A 3, C 4 and B 5.

## Link state: Dijkstra's invariant and the forwarding table
<!-- topics: cn-network-layer.link-state -->

**Claim.** With non-negative link costs, Dijkstra's algorithm from source $s$ keeps a tentative distance $D(v)$ for each router, repeatedly makes permanent the non-permanent router $w$ with the smallest $D(w)$, and relaxes $D(v) \leftarrow \min(D(v), D(w) + c(w, v))$ for each neighbour $v$ of $w$. When $w$ becomes permanent, $D(w) = d(w)$, the least cost from $s$. Recording the router $w$ that last lowered $D(v)$ as $v$'s predecessor gives a shortest-path tree, and the next hop for $v$ is the first router after $s$ on the tree path to $v$. The running time is $O(N^2)$ with an array and $O((N + E) \log N) = O(E \log N)$ with a binary heap on a connected network.

**Proof.** Tentative distances are always costs of real paths, so $D(v) \ge d(v)$ throughout. Suppose some router is made permanent with $D(w) > d(w)$, and take the first such $w$. On a least-cost path from $s$ to $w$, let $y$ be the first router that is not permanent at that moment and $x$ its predecessor on the path, which is permanent (possibly $x = s$). When $x$ was made permanent, $D(x) = d(x)$ by the choice of $w$, and the link $x$–$y$ was relaxed, so $D(y) \le d(x) + c(x, y) = d(y)$. Costs are non-negative, so $d(y) \le d(w)$ because $y$ lies on the path to $w$. Then $D(y) \le d(w) < D(w)$, so $w$ did not have the smallest tentative distance, a contradiction. Each router's predecessor is permanent before it, so following predecessors from $v$ reaches $s$ along a least-cost path, and its first router after $s$ is the next hop (CLRS gives this proof in full). Each of the $N$ selections scans an array in $O(N)$, and each link is relaxed in $O(1)$, for $O(N^2)$; with a heap each of the $N$ extractions and at most $E$ key decreases costs $O(\log N)$.

**GATE use.** The 2-mark MCQ gives a weighted topology and asks for one router's forwarding table or the order in which routers become permanent. The trap is the direct link: it is the next hop only when no cheaper path exists.

**Check.** Links A–B 1, B–C 1 and A–C 3: A reaches C at cost 2 via B, not 3 directly. On Kurose's six-router graph (u–v 2, u–w 5, u–x 1, v–x 2, v–w 3, w–x 3, w–y 1, x–y 1, w–z 5, y–z 2), router u gets v 2 via v, x 1 via x, y 2 via x, w 3 via x and z 4 via x. A script ran Dijkstra on both graphs.

## Distance vector versus link state: messages and outcome
<!-- topics: cn-network-layer.dv-vs-ls, cn-network-layer.link-state -->

**Claim.** In a connected network of $N$ routers and $E$ links, flooding one LSA (each router forwards the first copy it receives on every other link and discards duplicates) sends exactly $2E - N + 1$ messages and reaches every router. Flooding all $N$ LSAs sends $N(2E - N + 1) = O(N \cdot E)$ messages, after which every router holds the same map. One distance vector round sends $2E$ messages, one per link direction, each of $N$ entries. Once the network is stable both methods produce the same least costs, and they can differ only in the choice between equal-cost next hops.

**Derivation.** The origin $s$ sends the LSA on all $\deg(s)$ of its links. Each other router receives at least one copy, by induction on its hop distance from $s$ in a connected graph, and forwards only its first copy on its other $\deg(v) - 1$ links. The total is $\deg(s) + \sum_{v \ne s} (\deg(v) - 1) = \sum_v \deg(v) - (N - 1) = 2E - N + 1$, by the handshake identity $\sum_v \deg(v) = 2E$. Every router receives every LSA, so each holds every router's links, the whole graph. Sequence numbers let a router tell a newer LSA from an older one, so the maps agree once flooding ends. A distance vector router sends one vector per neighbour per round, which is $\sum_v \deg(v) = 2E$ messages. Dijkstra on the full map (previous section) and Bellman-Ford on the vectors (the Bellman-Ford section) both compute the least costs, so the stable tables agree on costs. Link state needs $O(E)$ memory per router for the map and a Dijkstra run per change, while a distance vector router stores only its neighbours' vectors. A wrong distance vector spreads into every table built from it, while a wrong LSA misdescribes only its own links.

**GATE use.** MCQs compare the two families: what each router knows, which counts to infinity, which floods, and the message or computation cost. The trap is believing the two can settle on different least costs in a stable network.

**Check.** A ring of 4 routers has $E = 4$: one LSA costs $8 - 4 + 1 = 5$ messages (2 from the origin, 1 from each neighbour, 1 from the far router's forward of its first copy), 20 for all four LSAs, against 8 vectors per distance vector round. A script matched $2E - N + 1$ against a flooding simulation from every origin on 200 random connected graphs.

## IPv6 header size and address compression
<!-- topics: cn-network-layer.ipv6-overview -->

**Claim.** The IPv6 base header is a fixed 40 bytes: version (4 bits), traffic class (8), flow label (20), payload length (16), next header (8), hop limit (8) and two 128-bit addresses. It has no checksum and no fragmentation fields. An address is written as eight 16-bit groups in hex. Leading zeros may be dropped within a group, and "::" may replace one run of all-zero groups, but only one, because two would make the number of zero groups in each run ambiguous.

**Derivation.** The field widths sum to $4 + 8 + 20 + 16 + 8 + 8 + 128 + 128 = 320$ bits, which is 40 bytes, and none of them is optional, so the header length needs no IHL field. Options and fragmentation move into extension headers chained by next header. Routers never fragment, so the identification, flags and offset fields are gone, and the source uses path-MTU discovery with a fragment extension header, relying on every link carrying at least 1280 bytes. The header checksum is dropped because link layers and transport checksums already cover errors, which also spares routers the per-hop recomputation that TTL forces in IPv4. Dropping leading zeros is reversible because each group is exactly four hex digits once padded on the left. A single "::" is reversible because the reader knows the address has 8 groups, so the run stands for 8 minus the number of explicit groups. With two "::" the reader knows only the total number of zero groups, and every split of that total into two runs of at least one group each gives a valid address.

**GATE use.** MCQs ask for the IPv6 header size, which IPv4 fields were removed (checksum, IHL, fragmentation fields) and which was renamed (TTL to hop limit), or which written form of an address is valid. The traps are 20 bytes carried over from IPv4 and accepting an address with two "::".

**Check.** 2001:0db8:0000:0000:0000:0000:0000:0001 compresses to 2001:db8::1. The string 2001::1::2 has 3 explicit groups, so its 5 zero groups split between the two runs as 1 and 4, 2 and 3, 3 and 2, or 4 and 1, giving four different addresses. The address space has $2^{128} \approx 3.4 \times 10^{38}$ addresses. A script summed the header widths and compressed the address with Python's ipaddress module.
